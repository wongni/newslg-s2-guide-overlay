# 개척 트래킹(S3/S4) 규칙과 교훈

`/pioneer`(저돌), `/pioneer-high`(고돌) 트래킹 표와 시즌별 가이드 데이터를 만들거나 고칠 때 참고. S4 트래킹을 만들면서 확인된 규칙과 실수를 정리한 것.

## 파일 구조

- 시즌: `src/data/season.ts` (`s2`/`s3`/`s4`, 기본 `s4`, 선택값은 `localStorage["activeSeason"]`). 시즌별 데이터는 `src/data/s{N}/`.
- 트래킹 데이터: `src/data/s{N}/tracking-common.json`(알아두기·준비·규칙·덱 카드·열 머리글) + `tracking.json`(저돌파 행) + `tracking-high.json`(고돌파 행). 병합과 저장 키는 `src/data/tracking-by-season.ts`. S2는 트래킹이 없어 S3를 쓴다.
- 화면: `src/components/SeasonTrackingTable.tsx`(시즌 선택) → `src/components/TrackingTable.tsx`(표). 타입은 `src/types/tracking.ts`.
- S4 가이드 탭 값: `src/data/s4/{guide-steps,tier-values,common-values,glossary}.json`. 돌파 구분은 원문 풀돌=고돌파, 중·고돌=중돌파/고돌파 값 사용.
- 진행 체크 저장 키는 시즌·돌파별로 분리(`s3-pioneer-tracking-progress`, `s4-pioneer-tracking-high-progress` 등). S3 키는 바꾸지 말 것(기존 체크 기록 유지).

## 계산 규칙 (S3 `tracking-common.json` 기준, S4도 동일 적용)

- 경험치: `cumulativeExp`는 5레벨=0 기준 누적선, `landExp`는 토지 결과 레벨별 경험치. 레벨 = 정수 레벨 + (누적 − 도달선) / 다음 레벨 필요량.
- 70% 규칙: 부대 레벨이 토지의 `fullExpMinLevel` 미만이면 경험치 ×0.7 (6레벨 땅 19, 7→24, 8→29, 9→34, 10→39, 11→41, 12→43).
- 체력: 시작 200. 결과 Lv3 이하 개간·점령은 10, Lv4 이상은 20 소모. 닭다리 1개 = +60. 소탕은 경험치만 얻음, 둔전은 경험치·체력 변화 없음.
- 검산 기준값: Lv1 개간 ×4 → 8.25 / 160, 이어서 Lv2 개간 ×2 → 9.31 / 140(원문 "도원 9레벨"). 계산 로직을 바꾸면 이 두 값이 유지되는지 먼저 본다.
- 퇴진한 부대는 레벨·체력이 그대로 유지된다. 새 장수를 명시적으로 넣을 때만 5 / 200으로 리셋. (교훈: 노동대를 6장에서 재편성하는데 5 / 200으로 다시 계산해 값이 어긋났음. 재편성은 보관한 값에서 이어간다.)
- **교체("A → B 교체")는 레벨을 서로 바꾼다.** B는 A의 레벨, A는 B의 원래 레벨이 된다. 체력은 두 부대 모두 레벨이 높은 부대의 체력으로 맞춰진다. 예: 개척2 21.2 / 40 → 개척3 교체 → 개척3 21.2 / 40, 개척2 5 / 40. 그래서 "아무 장수 → 개척2 교체"에서 개척2는 아무 장수의 레벨과 체력 200을 받는다. 아무 장수·보라 장수는 열이 없으므로 그쪽 값은 표에 남기지 않는다.
- 닭다리 지급과 한도 증가는 S3 표를 그대로 쓰고 **별도 행**으로 넣는다: "N장 완료 | 완료 | 개간지 한도 +2, 닭다리 +2"(2·3장은 닭다리만, 9장 +3, 10장 +4), "6장·번영도 4500 | 한도증가 | 영지 한도 +2"(7장 10000 +2, 8장 15000 +3, 10장 20000 +3). 한도증가 행은 그 장 완료 행 바로 앞. 개간지 한도는 4→16, 새 칸은 Lv3으로 생김. 점령지 한도는 10→20. 닭다리 열은 사용 수가 아니라 **보유 수**. 부족하면 전투를 멈추게 계산한다(체력 없이 계속 싸운 것으로 두지 말 것).
- **닭다리는 31레벨부터 사용할 수 없다.** 31레벨 미만에서 체력이 모자랄 때 먹고, 31레벨을 넘기기 직전에 남은 닭다리를 모두 먹는다(체력 상한 없음으로 가정). 31레벨 이상인 행에서 닭다리 보유 수가 줄면 안 된다. 현재 표는 고돌파는 9레벨 점령 중, 저돌파는 8레벨 소탕 중에 31을 넘기기 직전에 모두 먹는다.
- 수비대 레벨: 내성 N레벨 땅은 N+1 레벨 수비대.
- 개간 행의 대상 `LvN`은 S3처럼 **개간하는 땅의 현재 레벨**이다(Lv5 ×2를 개간하면 Lv6 2칸이 생김). 경험치·체력은 결과 레벨(N+1) 땅 기준으로 계산한다(S3 표: "Lv1 ×4" = Lv2 땅 경험치). 점령 행의 `LvN`은 점령하는 땅 레벨. (교훈: 한때 개간을 결과 레벨로 써서 표기가 섞였고, 6장 노동대 행은 Lv3 땅으로 계산되어 체력이 틀렸다. 개간 행을 바꾸면 개간지 현황의 칸 이동과 체력 소모(칸 수 × 10/20)가 맞는지 검산한다.)
- 개간 = 내성, 점령 = 외성이므로 대상에 "내성/외성"을 쓰지 않는다(행 49 같은 "내성 전부 12레벨" 문장은 예외).

## 표기 규칙 (S3 형식을 따른다)

- 챕터: 메인 퀘스트 장("2장", "10장 완료", "11장 이후"). S4 원문은 일차 기준이라 장 번호는 S3 임무 순서에 맞춘 **추정**이다. 일차는 하루가 바뀌는 행의 팁 앞("2일차 · …")과 "1일차 종료" 행의 대상에 남긴다.
- 부대: 덱 번호 `개척N`(S3 방식). S4는 개척1 노동대 · 2 동남만(2군에서는 남만방패) · 3 좌전녕 · 4 초남만 · 5 SP제갈량 남만방패. 북벌창은 개척5 카드의 대안 팁. 열 머리글은 `unitLabels`, 행 태그는 `(개척2 동남만)`.
- 편성·퇴진·교체 행은 태그 없이 쓴다. 행동 열에 이미 "퇴진/편성"·"교체"가 있으므로 대상은 "개척1 → 개척2", "개척2 → 개척3 교체"처럼 화살표로 쓴다(S4). "아무 장수 3명"/"보라 장수 3명"은 덱이 아니므로 번호 없이 쓴다.
- 대상에는 핵심(레벨×칸 수, 개척N 표기)만 쓰고 설명은 팁으로 옮긴다("자원지 기술 1레벨만", "목재:철:석재 = 3:3:4" 등).
- 팁은 "그 행동을 하려면 꼭 알아야 하는 것"만 남긴다. 같은 화면의 다른 곳에서 알 수 있는 내용은 쓰지 않는다: Lv/HP 열 값(목표 레벨, 1일차 종료 레벨), 닭다리 열, 개간지·점령지 현황, 알아두기(자원 비율, 군량 금지, 해제 규칙), 덱 카드(전법·스탯·덱 설명). 수비대 목록과 수치 같은 가이드 탭 내용도 반복하지 않는다. 남기는 것은 우선순위·피할 대상(장패 › 유엽, 여몽 피하기), 시작해야 하는 레벨(9레벨은 30레벨에), 시간대, 조건, 원문 주석이다. 일차 표시("2일차 · ")는 날이 바뀌는 행에만 둔다.
- "목표 레벨까지 돌린다"는 소탕이 아니라 개간/점령 행으로 쓴다. 소탕은 이미 점령한 땅을 치는 행동. 칸 수는 목표 레벨에 도달하는 전투 횟수로 계산해 `Lv5 ×7`처럼 적는다. 개간과 점령이 섞인 행은 두 행으로 나눈다.
- **9레벨 땅(9토)부터는 소탕하지 않고 점령한다.** 경험치·체력은 소탕과 같으므로 Lv/HP는 그대로이고 점령지 현황만 늘어난다. 점령지 한도(20)가 차면 가장 낮은 레벨 땅을 바꾼 것으로 계산한다.
- **내성 개간 우선.** 같은 레벨 땅을 칠 수 있으면 점령보다 개간을 먼저 한다. 외성 점령은 나중 소탕이나 둔전에 필요한 1칸(팁에 "9장 소탕용 외성 1칸"처럼 이유를 적음), 임무 조건, 원문이 지정한 땅(예: 3보라 장수 땅)일 때만 남긴다. 낮은 레벨 내성을 개간해 경험치를 손해 보지는 않는다. 예: 내성에 Lv4가 없으면 Lv5 목표 전투는 Lv3 개간이 아니라 점령으로 채운다. 전투 수와 땅 레벨이 같으면 구간이 끝난 뒤 Lv/HP·닭다리는 그대로이고, 나뉜 행의 중간값과 개간지·점령지 현황만 다시 계산한다.
- 레벨 표시는 `levelDecimals`(S4=1)로 화면에서만 반올림하고, 데이터에는 2자리 값을 둔다. 정수는 "5"로 쓴다.
- 부대 열은 비우지 않는다. 모든 덱이 시작 행에서 5 / 200이고, 바뀌지 않은 행은 직전 값을 `carried: true`로 이어받아 흐리게 표시한다. 퇴진한 덱도 값이 남는다.
- 값 정직성: 원문에 없는 수치(Lv/HP, 개간지·점령지 현황, 닭다리)는 계산한 추정치다. `tracking-common.json`의 알아두기에 그 사실과 계산 방식을 적어 둔다. 원문에 레벨이 적힌 시점(`tier-values.json`의 5·6·8·9레벨 목표, 1일차 종료, 10~12레벨 여는 레벨)은 기준점으로 맞춘다.

## 작업 방식 교훈

- **사용자가 파일을 직접 고친다.** 첫 행 대상 "-", 6장 "개척2 퇴진, 개척1 편성" 등. 일괄 변환 스크립트는 바꿀 필드만 쓰고, 실행 전에 해당 행을 읽어 사용자가 고친 값이 있는지 확인한다. 한 번 "복구"한 값이 사용자의 의도였던 적이 있다(행 0 대상 "-").
- **행을 나누거나 끼우면 인덱스 기반 설정이 전부 밀린다.** 닭다리 지급, 개간지·점령지 스냅샷, 덱 매핑이 모두 행 번호에 묶여 있다. 번호 변환 함수를 만들어 모든 표에 적용하고, 실행 전에 JSON을 백업한다. 변환식 오류로 "7장 완료 닭다리 +2"와 개간지 현황이 한 행씩 밀린 적이 있으니 실행 후 해당 행을 직접 출력해 확인한다.
- 이미 분리된 행을 다시 실행하면 중복되므로 스크립트는 "대상 행이 예상한 상태인지" 먼저 검사하고 아니면 중단하게 쓴다.
- **전투를 다른 행에 숨기지 않는다.** 예전 계산은 7레벨 전투를 교체 행에, 8레벨 소탕 22번을 "점령 Lv8" 한 행에 넣어서 1군이 30레벨까지 가는 과정이 표에 보이지 않았다. 레벨이 오르는 행은 반드시 개간/점령/소탕 ×N으로 쓰고, 교체·편성·완료 행에서는 레벨이 오르지 않게 한다(기준점 행은 예외). 원문의 "N레벨을 돌려 목표까지"는 점령 ×2(새 땅) + 소탕 ×N(목표 레벨까지)으로 나눈다.
- 닭다리 지급(2~8장 +2 등)은 팁에 적지 않는다. 닭다리 열의 보유 수 변화로 보이고, 지급 규칙은 알아두기에 있다. 예전 변환 스크립트가 팁에 "🍗 N장 완료 닭다리 +X"를 붙였으니, 계산 스크립트를 다시 쓸 때는 그 부분을 넣지 않는다.
- 원문이 서로 모순되면 임의로 해소하지 말고 사용자에게 묻는다. 사례: 1일차 "처음 4시간 기준 1군 29.5~30레벨"과 "8레벨 시작 24레벨", 남만방패/좌전녕의 2군 사용, "내성 9→10" 순서, 저돌파·명함 수치 부재. 답이 없을 때만 중간값·보수적 해석을 쓰고 그 사실을 알린다.
- 이름 변경 요청이 이어졌다(덱 이름 → 개척N 번호, 일차 → 장). 표기 방식은 요청이 오면 데이터 한 곳(`unitLabels`, 태그 치환, 장 매핑)에서 바꿀 수 있게 유지한다.
- PowerShell에서 한글이 든 인라인 `node -e`는 따옴표가 깨지고, `Get-Content`/`Set-Content` 기본 인코딩이 한글을 망가뜨린다. 변환 스크립트는 `fs_write`로 `.kiro/tmp/*.js`에 만들고 Node에서 UTF-8로 읽고 쓴 뒤 실행 후 삭제한다.

## 검증 체크리스트

1. `npx tsc --noEmit -p tsconfig.json` 통과.
2. 행 수, 닭다리 최종 보유 0·사용 21(저돌파는 부족해 일부 전투가 줄 수 있음), 모든 행·모든 덱에 값이 있는지(`carried` 포함).
3. 기준점 일치: 1일차 종료(고돌파 34 / 24), 2일차 종료(39.9 / 31), 5·6·8·9레벨 목표.
4. 브라우저: dev 서버(`npm run dev`, 3000)에서 `/pioneer`, `/pioneer-high`. 시즌은 마운트 후 `localStorage`로 바뀌므로 이동 직후가 아니라 **몇 초 기다린 뒤** 읽는다. 테이블은 행 수로 찾는다. 확인 후 `activeSeason`을 `s4`로 되돌린다.
5. S3 회귀: 제목 "S3 개척 트래킹", 부대 열 3개, 흐린 값 0, 행 48개.
6. 스크린샷·임시 스크립트·백업을 저장소 안에 남기지 않는다.

## 알려진 한계

- 장 번호와 체력 회복 시점은 추정이다. 개간지·영지 한도는 S3 값을 가져온 것이라 S4에서 다를 수 있다.
- 2일차 종료 행의 개척5는 1군 값만 열에 두고 2군 값(31)은 팁에 둔다(한 덱이 두 칸 값을 동시에 표시할 수 없음).
- 저돌파는 닭다리가 2개 모자라 일부 전투가 계산에서 빠진다.
- 이어받은 값은 데이터에 직접 들어 있어, Lv/HP를 다시 계산하면 이어받기 처리도 다시 해야 한다.
